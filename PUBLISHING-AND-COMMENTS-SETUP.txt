TECUR: PUBLISHING, ARTICLE PICTURES AND COMMENTS UPDATE

This is an update only. Do not delete your website or replace its entire dist folder.
Back up your current project, then copy the included files into the matching paths.
When Windows asks, replace files with the same names. Keep every other existing file.

FILES
Replace these existing files:
  dist/assets/public-content.js
  dist/assets/admin-content.js
  dist/assets/firebase.js
  dist/assets/catalog.js
  firestore.rules
  firebase.json
Add these new files:
  dist/assets/comments.js
  dist/assets/comments.css
  firestore.indexes.json

Your dist/assets/config.js is deliberately NOT included. Keep your current connection
settings and App Check key. No HTML replacement or new npm package is required.
If you have customised firebase.json, keep those changes and add only
"indexes": "firestore.indexes.json" inside its existing "firestore" object.
If you already have firestore.indexes.json, MERGE the included comments index into
your existing indexes array instead of discarding your other indexes.
If you have customised Firestore rules, merge the new commentLimits and comments
rules and the safe admin() helper while retaining your unrelated collections.

REQUIRED ACTIVATION
1. Publish the new Firestore rules to project tecur-automotive.
2. Deploy the included comments index. In the VS Code project terminal, with the
   project dependencies already installed and the CLI signed in, run:
   npx firebase deploy --only firestore:rules,firestore:indexes --project tecur-automotive
   If the CLI is not signed in, first run: npx firebase login
   Wait for the comments index to finish building before testing comments.
3. In Firebase Console > Authentication > Sign-in method, enable Anonymous sign-in.
   Visitors do not need to fill a registration form. This provides an identity for
   their comments and likes. Existing authorised admin sign-in stays unchanged.
4. Publish the changed dist/assets files through your existing hosting process
   (for example, push them to GitHub and let your website host redeploy).
   Updating database rules alone DOES NOT update the website JavaScript.
5. Refresh the website and admin page with Ctrl+Shift+R.

MANUAL INDEX OPTION
Firestore Database > Indexes > Composite > Add index:
  Collection ID: comments
  Query scope: Collection
  parentId: Ascending
  createdAt: Descending
Publish firestore.rules separately through the Rules tab if not using the CLI.

ARTICLE PICTURES
In the article editor, choose a cover picture from your device. JPEG, PNG and WebP
under 5 MB are accepted. You can still use a cover URL. A selected file replaces
that URL when you save. The existing Insert image button adds pictures inside
the article, including multiple pictures. The cover appears on the homepage card
and the article page. Uploads use your existing blogmedia Storage permissions.
Do not make Storage publicly writable. If uploads fail, confirm that the deployed
Storage rules allow authorised admins to write blogmedia, as in the original project.

PUBLISHING
Choose Published in the editor, then save. Draft and Archived items stay hidden.
Articles now load independently of pop-ups and update live. The public article
reader loads its specific post directly, including posts outside the homepage list.
The homepage shows up to six articles and three listings, with featured listings
first. The full parts catalogue updates live and removes unpublished entries.
Read errors now show a message instead of silently hiding the failure.

COMMENTS AND ADMIN REPLIES
Readers can post comments, reply within a conversation and like/unlike comments
or replies. One like per signed-in visitor identity is allowed. New comments have
a server-enforced 15-second cooldown per identity. Anonymous identities can reset
when sessions are cleared, so this is not a guarantee of one identity per person.
Keep your existing App Check protection correctly configured for public traffic.
Do not disable protection to resolve a setup error.

For admin replies, sign in to the admin section, then click
"View article / reply to comments" on a published post. It opens in the SAME TAB
so the admin session remains available. Your reply receives a verified Admin label.
Visitors cannot grant themselves this label. Admins can remove comments. Removing
a root comment hides its conversation in the interface; it does not delete all
stored reply documents. Likes update after interaction or page refresh.

The discussion shows the latest 25 root comments and up to 50 replies per thread.
This update adds discussions to admin-published articles at /blog/?id=... .
The prewritten static car-guide pages do not receive comment threads in this patch.

CHECK AFTER DEPLOYMENT
Publish an article with a cover picture and open the homepage in a private browser
window. Open the article, post a reader comment, like it and add a reply. Return to
your signed-in admin tab and reply through the article link. Confirm the Admin label.
If posts still do not load, open browser Developer Tools > Console and copy the
error next to "Article feed could not load" or "Live content connection failed".
Permission errors can indicate a project, rules, domain or App Check configuration
problem. This patch cannot verify settings in your live Firebase account.

Firestore emulator tests passed for published-only access, author identity,
